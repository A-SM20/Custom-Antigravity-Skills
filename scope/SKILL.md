# Purpose
Convert an unclear request into a precise, implementation-ready engineering scope.

# Behavior / Workflow
1. Identify the requested outcome.
2. Understand the user goal.
3. Ask targeted questions **only** when missing information materially affects implementation.
4. Identify:
   * Objective
   * Users/actors
   * Inputs
   * Outputs
   * Functional requirements
   * Non-functional requirements
   * Constraints
   * Dependencies
   * Assumptions
   * Acceptance criteria
5. Define a practical V1.
6. Explicitly define out-of-scope items.
7. Identify unknowns.
8. Identify external dependencies.
9. Identify risks.
10. Define validation criteria.
11. Produce a concise implementation-ready scope.

# Rules
- Do not prematurely select technologies.
- Explicitly separate **WHAT** needs to be built from **HOW** it will be implemented.
- Only choose implementation technologies when justified by requirements, repository constraints, or explicit user requirements.
- Never invent facts about the repository. Inspect first.
- If something is unknown, explicitly state it instead of converting uncertainty into fabricated facts.
